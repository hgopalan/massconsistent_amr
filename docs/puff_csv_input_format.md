# Puff Model: Unified CSV Input Format

## Overview

The puff model accepts configuration through an input file (`.i` format) and supplementary CSV files for data-heavy inputs. This document specifies the CSV input schemas, formats, and usage examples.

## Input File Organization

```
├── inputs.i                    # Main solver configuration (ParmParse format)
├── wind_field.csv            # Wind field (optional: uniform, gridded, or timeseries)
├── sources.csv               # Multiple sources (optional, future)
├── met_profiles.csv          # Meteorological profiles (optional, future)
├── receptors.csv             # Receptor locations (already supported)
├── chemistry.csv             # Chemical reaction matrix (optional, future)
└── deposition_params.csv     # Deposition parameters (optional, future)
```

## Configuration File (inputs.i)

### Wind Field Configuration

New parameters in `inputs.i`:

```
# Wind field input configuration
wind_field_file = "wind_field.csv"      # Path to wind field CSV (optional)
wind_field_format = "uniform"           # Format: "uniform", "gridded", or "timeseries"
enable_unsteady_wind = false            # Enable time-varying wind fields
wind_field_start_time = 0.0             # Start time for wind field [s]

# Multi-source configuration
sources_file = "sources.csv"            # Path to multiple sources CSV (optional)

# Meteorological profiles
met_profile_file = "met_profiles.csv"   # Meteorological profile CSV (optional)
enable_spatial_met = false              # Enable spatially-varying meteorology
```

**Backward Compatibility:**
- If `wind_field_file` is empty, solver uses legacy `U_wind`, `V_wind`, `W_wind` parameters
- All new parameters are optional; sensible defaults apply if omitted

## CSV Formats

### Wind Field CSV: Uniform Format

Single uniform wind field for entire domain and time.

**Format:** `uniform`

**Columns:**
| u | v | w |
|---|---|---|

**Example:**
```
# Wind Field CSV Format
# Description: Uniform 10 m/s westerly wind
# Format: uniform

u,v,w
10.0,0.0,0.0
```

**Generated by:**
```bash
python wind_field_converter.py --uniform 10.0 0.0 0.0 --output wind_field.csv
```

### Wind Field CSV: Gridded Format

Wind field defined at discrete grid points. Supports structured or unstructured grids.

**Format:** `gridded`

**Columns:**
| x | y | z | u | v | w |
|---|---|---|---|---|---|

All values in SI units: coordinates in [m], wind in [m/s].

**Example:**
```
# Wind Field CSV Format
# Description: Gridded wind field from WRF model
# Format: gridded
# Grid dimensions: 10 x 10 x 5

x,y,z,u,v,w
0.0,0.0,0.0,9.8,-0.1,0.0
50.0,0.0,0.0,9.9,-0.2,0.01
100.0,0.0,0.0,10.0,-0.1,0.0
...
```

**Interpolation:**
- Default: nearest-neighbor interpolation to puff location
- Future: linear interpolation support

**Generated by:**
```bash
python wind_field_converter.py --input wrf_output.nc --format wrf --output wind_field.csv
python wind_field_converter.py --input wind_grid.txt --format ascii --output wind_field.csv
```

### Wind Field CSV: Time-Series Format

Wind field varying in time (uniform in space, varying in time).

**Format:** `timeseries`

**Columns:**
| time | u | v | w |
|------|---|---|---|

Time in [s], wind in [m/s].

**Example:**
```
# Wind Field CSV Format
# Description: Time-varying uniform wind
# Format: timeseries
# Number of time steps: 5

time,u,v,w
0.0,8.0,0.5,0.0
60.0,9.0,0.3,0.0
120.0,10.0,0.1,0.0
180.0,9.5,0.2,0.0
240.0,8.5,0.4,0.0
```

**Interpolation:**
- Linear interpolation between time steps
- Extrapolation: hold last value constant

**Requirements:**
- Time steps must be sorted ascending
- `enable_unsteady_wind = true` in inputs.i to activate time-series reading

### Receptor CSV (Existing)

Location and metadata for concentration output points.

**Columns:**
| x | y | z | label |
|---|---|---|-------|

**Example:**
```
x,y,z,label
100.0,150.0,1.5,Receptor_1
200.0,150.0,1.5,Receptor_2
150.0,250.0,1.5,Receptor_3
```

## Usage Examples

### Example 1: Basic Setup with Uniform Wind

**inputs.i:**
```
enable_puff = true
source_x = 150.0
source_y = 150.0
source_z = 10.0
emission_rate = 1.0
K_h = 1.0
K_v = 0.5
xmin = 0.0
xmax = 300.0
ymin = 0.0
ymax = 300.0
zmin = 0.0
zmax = 100.0
dx = 10.0
dy = 10.0
dz = 10.0
dt_puff = 0.5
n_steps_puff = 100
puff_output = concentration.csv

# Use CSV wind field instead of U_wind, V_wind, W_wind
wind_field_file = "wind_field.csv"
wind_field_format = "uniform"
```

**wind_field.csv:**
```
# Wind Field CSV Format
# Description: 10 m/s easterly wind
# Format: uniform

u,v,w
10.0,0.0,0.0
```

**Run:**
```bash
./puff_solver inputs.i
```

**Convert WRF NetCDF to CSV:**
```bash

  --input wrfout_d01_2023-06-15_00_00_00 \

  --output wind_field.csv \
  --description "WRF hourly wind"

enable_puff = true

source_z = 10.0
emission_rate = 1.0

wind_field_file = "wind_field.csv"
wind_field_format = "gridded"
```

## Column Headers and Delimiter

- **Delimiter:** Comma (`,`)
- **Header row:** First data line with column names (not optional)
- **Metadata:** Lines starting with `#` are comments/metadata
- **Blank lines:** Skipped; can be used for readability

## Validation

The puff solver performs the following validation:

1. **File existence:** Warns if CSV file not found; falls back to defaults
2. **Format detection:** Automatically detects format from metadata or column count
3. **Column count:** Validates expected number of columns per format
4. **Numeric values:** Skips lines with non-numeric values
5. **Consistency:** For gridded format, prints grid dimensions

## Error Handling

**Missing wind field file:**
- If `wind_field_file` specified but file not found → warning, use fallback `U_wind`, `V_wind`, `W_wind`
- If fallback also empty → warning, assume zero wind (U=V=W=0)

**Malformed CSV:**
- Lines with parsing errors → skipped
- Insufficient columns → skipped
- Format mismatch → warning printed

## Performance Considerations

- **Uniform wind:** Minimal memory overhead; O(1) lookup
- **Gridded wind:** Memory scales with number of grid points; O(n) nearest-neighbor lookup
- **Time-series wind:** Memory scales with number of time steps; O(log n) binary search for interpolation

## Future Extensions

Planned CSV input files (not yet implemented):

- `sources.csv` – Multiple simultaneous sources
- `chemistry.csv` – Custom chemical reaction matrix
- `deposition_params.csv` – Pollutant-specific deposition velocities
- `met_profiles.csv` – Spatially-varying meteorological profiles
