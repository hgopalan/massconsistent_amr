## 5-Minute Quick Start

### Step 1: Understand the Purpose

Phase 4 validates that synthetic turbulent fluctuations generated by Phases 1-3 are:
- Physically correct (conserve energy, satisfy continuity)
- Realistic (match atmospheric turbulence statistics)
- Formatted correctly (OpenFAST compatible)

## Usage Examples

### Example 1: Validate Von Kármán Spectrum

```cpp
// Setup parameters
amrex::Real u_rms = 1.0;           // m/s
amrex::Real length_scale = 300.0;  // m
amrex::Real u_mean = 10.0;         // m/s
int num_frequencies = 256;

// Generate frequency grid (logarithmic)
std::vector<amrex::Real> frequencies(num_frequencies);
std::vector<amrex::Real> spectrum_u(num_frequencies);

for (int i = 0; i < num_frequencies; ++i) {
    amrex::Real f_min = 0.001;
    amrex::Real f_max = 10.0;
    frequencies[i] = f_min * std::pow(f_max/f_min, 
                                      (amrex::Real)i/num_frequencies);
    
    // Compute Von Kármán spectrum
    spectrum_u[i] = VonKarmanSpectrumValidator::ComputeSpectrum(
        frequencies[i], u_rms, length_scale, u_mean);
}

// Validate
auto result = SpectralValidator::ValidateSpectrum(
    spectrum_u.data(), frequencies.data(), num_frequencies,
    u_rms, length_scale, u_mean, true);

if (result.all_checks_passed) {
    std::cout << "✓ Spectrum validated\n";
    std::cout << "  Energy error: " << result.energy_error*100 << "%\n";
    std::cout << "  Peak frequency: " << result.observed_peak_freq << " Hz\n";
} else {
    std::cout << "✗ Validation failed\n";
}
```

### Example 2: Validate Physics

```cpp

amrex::Real target_intensity = 0.14; // 14%

// Validate

    u_field.data(), v_field.data(), w_field.data(),

    std::cout << "✓ All physics checks passed\n";

```

## Physics Parameters & Typical Values

### Atmospheric Turbulence

```
Turbulence Intensity Profile:
  I(z) = I_ref · (z / z_ref)^α
  
  Typical values:
  - I_ref = 0.12-0.16 (@ 10m)
  - α = 0.10-0.20 (power-law exponent)
  - Smooth terrain: I ≈ 0.10
  - Rough terrain: I ≈ 0.18
  - Complex terrain: I ≈ 0.25

Component Anisotropy:
  - v_rms / u_rms ≈ 0.80 (lateral)
  - w_rms / u_rms ≈ 0.50 (vertical)
  - These ratios are stable across height

Integral Length Scales:
  - L_u ≈ 300 m (typical at hub height)
  - L_v ≈ 200 m (≈ 0.67·L_u)
  - L_w ≈ 100 m (≈ 0.33·L_u)

Cross-Correlations:
  - ρ_uv ≈ -0.25 (weak negative)
  - ρ_uw ≈ 0.10 (very weak)
  - ρ_vw ≈ 0.00 (negligible)
```

## Common Issues & Solutions

### Issue 1: Energy Not Conserved

**Problem:** Energy error > 5%

**Possible Causes:**
1. Too coarse frequency discretization (need >128 bins)
2. Frequency range too narrow (need 0.001-10 Hz)
3. Numerical integration errors

**Solution:**
```cpp
// Use logarithmic frequency spacing
int num_freq = 256;  // Use power of 2
amrex::Real f_min = 0.001;
amrex::Real f_max = 10.0;

// Adequate frequency range
// Check integration carefully
```

### Issue 2: Anisotropy Ratios Off

**Problem:** v/u or w/u not matching 0.80 / 0.50

**Possible Causes:**
1. Phase 1 anisotropy ratios wrong
2. Phase 2 not applying amplitude scaling
3. Numerical noise

**Solution:**
```cpp
// Check Phase 1 parameters
params.anisotropy_ratio_v = 0.80;  // ±5%
params.anisotropy_ratio_w = 0.50;  // ±5%

// Verify Phase 2 scaling
A_v = sqrt(anisotropy_v) * A_u;
A_w = sqrt(anisotropy_w) * A_u;
```

### Issue 3: Continuity Violated

**Problem:** Average divergence > 10% of gradient scale

**Possible Causes:**
1. FFT artifacts at boundaries
2. Coarse grid spacing
3. Unphysical field generation

**Solution:**
```cpp
// Ensure proper boundary handling in Phase 2
// Use finer grid if needed
// Check FFT implementation

// Add small divergence correction if needed
// (optional post-processing)
```

### Issue 4: OpenFAST Format Error

**Problem:** BTS file not readable by OpenFAST

**Possible Causes:**
1. Wrong header structure
2. Endianness mismatch
3. Data layout incorrect

**Solution:**
```cpp
// Verify BTS header (from Phase 3)
// id1, id2 = 7
// nt, ny, nz correct
// dt, uHub, zHub valid

// Check data layout: x (fast), y, z (slow)
// Time-stacking: t=0 (all points), t=1 (all points), etc.
```
