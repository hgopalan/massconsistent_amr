## Mathematical Foundations

### 1. Spectral Energy Conservation (Parseval's Theorem)

**Theory:**
```
∫₀^∞ S_u(f) df = σ_u²

For discrete frequencies:
Σᵢ S_u(fᵢ) · Δfᵢ ≈ σ_u²  (within ±5% tolerance)
```

**Validation Approach:**
- Compute spectral integral from generated fields
- Compare against target RMS velocity
- Acceptable error: ±5% (accounting for discretization)

**Implementation:**
```cpp
amrex::Real integrated_energy = 0.0;
for (int i = 0; i < num_frequencies; ++i) {
    integrated_energy += spectrum[i] * delta_f[i];
}

amrex::Real target_energy = u_rms * u_rms;
amrex::Real error = |integrated_energy - target_energy| / target_energy;
ASSERT(error < 0.05);
```

### 2. Von Kármán Spectrum Validation

**Model:**
```
S_u(f) = (4·L_u·u_rms²) / (1 + 70.8·(f·L_u/U)²)^(5/6)

Properties:
- Peak frequency: f_peak ≈ 0.029·U/L_u
- High-frequency decay: S(f) ∝ f^(-5/3)
- Energy: ∫S df = u_rms²
```

**Validation Checks:**
1. **Peak Frequency Location** — Within ±50% of theoretical
2. **High-Frequency Slope** — log(S₂/S₁)/log(f₂/f₁) ≈ -5/3
3. **Energy Conservation** — As above

### 3. Kaimal Spectrum Validation

**Model:**
```
S_u(f) = (4·L_u·u_rms²·f̂) / (1 + 6·f̂)^(5/3)
where f̂ = f·L_u/U

Properties:
- Peak frequency: f_peak ≈ 0.093·U/L_u (higher than Von Kármán)
- More realistic for atmospheric boundary layer
- Still decays as f^(-5/3) at high frequencies
```

### 4. Integral Length Scale Recovery

**Theory:**
From autocorrelation function:
```
L_u = ∫₀^∞ ρ(Δ) dΔ

Via Wiener-Khinchin theorem (frequency domain):
L_u = (π/2U) · ∫₀^∞ S(f)/f df
```

**Validation:**
- Extract length scale from spectrum
- Compare against input L_u
- Acceptable error: ±20% (accounting for estimation uncertainty)

### 5. Mass Continuity

**Theory (Incompressible Flow):**
```
∇·u = ∂u/∂x + ∂v/∂y + ∂w/∂z = 0

For fluctuations (divergence-free):
∇·u' ≈ 0  (numerically small)
```

**Validation:**
- Compute divergence at interior grid points
- Average magnitude: <|∇·u|> / <|∇u|> < 10%
- Expected from mass-consistent solver

### 6. Anisotropy Ratios

**Atmospheric Turbulence Characteristics:**
```
Typical ratios:
v_rms / u_rms ≈ 0.80 ± 0.05  (lateral component)
w_rms / u_rms ≈ 0.50 ± 0.05  (vertical component)

These ratios are:
- Stable across height ranges
- Observed in field measurements
- Enforced by Phase 1 turbulence model
```

### 7. Coherence Decay

**Properties:**
```
Coherence function Coh(Δ):
- Coh(0) = 1.0  (perfect correlation at zero lag)
- Coh(∞) → 0    (independence at large separation)
- Monotonic decreasing
- Bounds: 0 ≤ Coh ≤ 1

Exponential decay:
Coh(Δ) = exp(-k·Δ)

Gaussian decay:
Coh(Δ) = exp(-k·Δ²)
```

### 8. Cross-Correlations

**Typical Atmospheric Values:**
```
ρ_uv = E[u'·v'] / (σ_u·σ_v) ≈ -0.2 to -0.3  (weak negative)
ρ_uw = E[u'·w'] / (σ_u·σ_w) ≈ -0.1 to +0.2  (very weak)
ρ_vw = E[v'·w'] / (σ_v·σ_w) ≈ 0.0          (negligible)

Physical bounds:
|ρ_xy| ≤ 1 for all components
Realistic magnitude: |ρ_xy| < 0.5
```

### 9. Turbulence Intensity

**Definition:**
```
I(z) = u_rms(z) / U_mean(z)

Typical range: 0.01 ≤ I ≤ 0.30
- Smooth terrain: I ≈ 0.10
- Rough terrain: I ≈ 0.15-0.20
- Complex terrain: I ≈ 0.20-0.30
```

## Implementation Structure

### File 1: `src/phase4_spectral_validation.H`

**Size:** ~420 lines (C++ header)

**Components:**

#### A. SpectralEnergyValidator
- `ComputeIntegratedEnergy()` — Numerical integration of spectrum
- `ValidateEnergyConservation()` — Check against Parseval's theorem
- `ComputeEnergyError()` — Diagnostic error calculation

#### B. VonKarmanSpectrumValidator
- `ComputeSpectrum()` — Reference Von Kármán spectrum
- `ValidatePeakFrequency()` — Check peak location
- `ValidateHighFrequencyDecay()` — Check f^(-5/3) slope

#### C. KaimalSpectrumValidator
- `ComputeSpectrum()` — Reference Kaimal spectrum
- `ValidatePeakFrequency()` — Kaimal-specific peak location

#### D. IntegralLengthScaleValidator
- `RecoverLengthScaleFromSpectrum()` — Extract L_u from spectrum
- `ValidateLengthScale()` — Compare against input

#### E. SpectralValidator (Master Class)
- `ValidateSpectrum()` — Comprehensive check (combines all above)
- Returns `ValidationResult` with individual check status

**GPU Compatibility:** 100% (all functions marked `AMREX_GPU_HOST_DEVICE`)

### File 2: `src/phase4_continuity_validation.H`

**Size:** ~470 lines (C++ header)

**Components:**

#### A. ContinuityValidator
- `ComputeDivergence()` — Finite-difference divergence at grid point
- `ComputeAverageDivergenceMagnitude()` — Domain average
- `ValidateContinuity()` — Check against tolerance

#### B. AnisotropyValidator
- `ComputeComponentRms()` — RMS for u, v, w components
- `ValidateVtoURatio()` — Check v/u ≈ 0.80
- `ValidateWtoURatio()` — Check w/u ≈ 0.50

#### C. CoherenceDecayValidator
- `ComputeAutocorrelation()` — Lag-dependent correlation
- `ValidateCoherenceAtOrigin()` — Check ρ(0) ≈ 1
- `ValidateMonotonicDecay()` — Check monotonic decrease
- `ValidateCoherenceBounds()` — Check 0 ≤ ρ ≤ 1

#### D. CrossCorrelationValidator
- `ComputeCrossCorrelation()` — Between-component correlations
- `ValidateUVCrossCorrelation()` — Specific checks for u-v
- `ValidateCrossCorrelationMagnitude()` — General bounds

#### E. TurbulenceIntensityValidator
- `ComputeIntensity()` — I = u_rms / U_mean
- `ValidateIntensityBounds()` — Check range [0.01, 0.30]
- `ValidateIntensityProfile()` — Compare against target

#### F. PhysicsValidator (Master Class)
- `ValidatePhysics()` — Comprehensive check (combines all above)
- Returns `ValidationResult` with all check status

**GPU Compatibility:** 100%

## Design Decisions

### 1. **Header-Only Modules**
- No separate compilation required
- Easy integration with existing code
- Template-friendly for GPU portability

### 2. **GPU-First Design**
- All functions marked `AMREX_GPU_HOST_DEVICE`
- No CPU-GPU synchronization overhead
- Scales to large domains on GPUs

### 3. **Comprehensive Over Minimal**
- Multiple validation approaches per property
- Catches edge cases
- Provides diagnostic information

### 4. **Python Test Framework**
- Easy to extend with new tests
- Clear failure diagnostics
- Compatible with CI/CD pipelines

### 5. **Tolerance Selection**
- Based on physical uncertainty
- Conservative (stricter than necessary)
- Can be tuned per application
